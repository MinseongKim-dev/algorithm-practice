                변수명(sorted_arr, length, answer)이 명확함 — 나중에 본인이 다시 봐도 헷갈리지 않습니다. 이 습관 계속 유지하십시오
- 배운 점/복습 포인트: 
(1) 시간복잡도 인식

sorted()는 **O(N log N)**입니다. 지금 이 문제는 N이 작아서 문제없지만, "정렬해서 중간값을 구한다"는 접근 자체를 의식적으로 인지하고 있어야 합니다.

나중에 마주칠 심화 버전: N이 매우 크고 "이 배열에서 k번째로 작은 값"을 자주 구해야 한다면, 매번 정렬(O(N log N))하는 건 비효율적입니다. 이럴 때 **퀵셀렉트(Quickselect)**라는 O(N) 평균 시간복잡도 알고리즘이 존재합니다. 지금 알 필요는 없지만, "정렬 없이도 중앙값을 구하는 방법이 있다"는 것만 기억해두십시오. Level 2~3 가면 이런 최적화 문제가 나옵니다.

(2) 엣지 케이스 — 빈 배열
python
array = []
solution(array)  # length=0, length//2-1 = -1 → 인덱스 에러 또는 이상한 값

프로그래머스 문제 제약조건에 보통 "배열 길이 ≥ 1" 같은 조건이 있어서 지금은 안 터지겠지만, 제약조건을 확인하는 습관을 지금부터 들이십시오. 실전에서는 "이 제약조건 덕분에 이 엣지케이스는 안 나온다"를 스스로 확인하고 넘어가는 것과, 확인 안 하고 운 좋게 통과하는 건 다릅니다.

(3) 반환 타입 — 짝수일 때 float
python
sorted_arr = [1, 2, 3, 4]
(sorted_arr[1] + sorted_arr[2]) / 2  # = (2+3)/2 = 2.5 (float)

sorted_arr = [1, 2, 3, 4, 5, 6]
(sorted_arr[2] + sorted_arr[3]) / 2  # = (3+4)/2 = 3.5 (float)

# 근데 만약 두 값이 짝수 합이면?
sorted_arr = [2, 4]
(2 + 4) / 2  # = 3.0 (float, 정수처럼 보이지만 실제로는 float)

지금 문제는 통과했겠지만, /는 항상 float를 반환한다는 걸 명확히 인지하고 있어야 합니다. 만약 문제가 "정수를 반환하라"고 명시했는데 3.0을 반환하면, 채점 방식에 따라 틀릴 수도 있습니다 (프로그래머스는 보통 관대하지만, 다른 플랫폼이나 실무 코드에서는 타입 불일치가 버그가 됩니다).

3. 더 짧게 쓰는 방법 (참고용, 지금 꼭 안 써도 됨)
python
def solution(array):
    sorted_arr = sorted(array)
    n = len(sorted_arr)
    return (sorted_arr[n//2] + sorted_arr[(n-1)//2]) / 2

원리: 홀수든 짝수든 이 한 줄로 다 처리됩니다.

홀수(n=5): n//2 = 2, (n-1)//2 = 2 → 같은 인덱스 두 번 더해서 나누기 = 자기 자신
짝수(n=4): n//2 = 2, (n-1)//2 = 1 → 중간 두 값의 평균

주의: 지금 당장 이걸 외워서 쓰라는 게 아닙니다. 오히려 본인이 짠 if/else 버전이 가독성 면에서 더 나을 수도 있습니다. 코드 골프(짧게 쓰기)가 항상 좋은 건 아닙니다. 이건 "이런 패턴도 있다" 정도로만 알아두시고, 본인 스타일대로 if/else로 명확하게 짜는 게 지금 단계에서는 더 좋은 습관입니다.
